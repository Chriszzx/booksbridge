# 架构

## 分层与职责

| 层 | 核心组件 | 职责 |
|---|---|---|
| BooksBridgeCore | BooksStore、EpubDocument、AccessibilityReader、ReadingCoordinator | 读取本地 EPUB、目录、Books 活跃窗口、可见文字和划选 |
| BooksBridgeLLM | BookMap、ReadingSnapshot、ScopedReading | 本地章节地图、对话阅读位置、统一原文边界 |
| BooksBridgeLLM | ContextBuilder、PromptBuilder、ChatClient、BookStatistics、ChapterSummarizer | 预算内上下文、单次问答请求、手动范围摘要 |
| BooksBridgeApp | AppDelegate、ReadingAssistant | 指令分发、一次位置刷新、问答编排 |
| BooksBridgeApp | SummaryJobs、ConversationStore | 独立后台摘要任务、对话和状态持久化 |
| BooksBridgeApp | WebBridge、WebUI | WKWebView 消息、Markdown、范围与位置展示 |

Core 与 LLM 不依赖 App。SQLite、网络、界面使用系统库，Swift 包没有外部依赖。
Markdown 由随源码打包的 Marked 与 DOMPurify 渲染和清理。

## 本地导入与章节地图

进入书籍时按 EPUB spine 顺序读取正文，并解析 EPUB 3 TOC、EPUB 2 NCX、目录锚点和 XHTML 标题。
一个章节可以横跨多个文件，一个文件也可以包含多个章节。没有目录或标题时明确标记为文档区段，不伪造原书章号。
目录中的 page-list 不作为章节。无法读取的正文文件导致明确错误，不悄悄遗漏内容。

`maps/` 只保存标题、层级、来源 href、规范化字符边界和完整正文指纹，不保存正文副本。
正文仍来自本地 EPUB；刷新时重新校验源文件。导入、构建地图和检查位置都不调用 LLM。

## 位置刷新与对话归属

侧栏和菜单栏监测 Books 当前活跃窗口。文件变化、应用激活和一秒轮询触发检测；
唤起应用和打开菜单也刷新。「现在在读」是提示，点击后才把书加入 BooksBridge 书库。

每个对话绑定一本书，保存自己的 `ReadingSnapshot`：书籍 ID、源指纹、页尾边界、章名、进度和捕获时间。
新建/打开对话、发送问题、检查原文、读取划选或生成摘要，统一经过 `refreshConversation`：

1. 读取对话绑定书籍的本地正文，重建/校验章节地图。
2. 活跃内容属于同一本书时，以可见文字在原文中的唯一匹配确定页尾。
3. 活跃书籍暂时没有可用正文时，校验书籍 ID、当前原文指纹、书库进度、CFI/记录更新时间与可见页码标记后，才复用同书有效位置；无页码标记时仅接受 15 秒内且带数据库位置/更新时间的观察。证据变化则拒绝旧边界，不用百分比猜测截断点。
4. 没有同书活跃内容时，已有对话保留自己的最后有效位置；新对话可使用该书的已验证位置，并明确显示「沿用上次位置」。没有有效位置时保留可用的书库进度、标记页末未定位；无效快照不算已复用。受限范围不能请求，全书范围仍可使用本地全文。
5. 有活跃文字但无法可靠定位时明确报错，不把错误当成无活跃内容，不静默沿用旧位置。

`BookPositionTracker` 把实时采集接入后台本地验证，按来源 ID 隔离任务，最多在内存保留 8 本书。尚未导入的书不创建书库记录、不落盘正文；添加时等待尚在进行的验证，关闭“先切窗口后完成解析”的竞态。已导入书的 `StoredBook.verifiedPosition` 保存在本 app 的 store.json，原文和采集样本不写入缓存。删除书籍/重新连接时取消对应任务，晚到结果不能重建记录。源别名只有明确关联后才能映射到同一本 app 书籍。

另一本文本不会替换当前对话的书籍。文件指纹变化后旧位置失效。
每次请求冻结自己的位置；流式回答期间翻页不会改变本次输入。
CFI 仅辅助定位文档，不能把节点字符偏移当成整章百分比。

## 三档读取边界

| 模式 | 可读取的原文 |
|---|---|
| 读到这为止 | 书首到当前页末尾，包含之前全部正文 |
| 整章（含未读） | 书首到当前目录节/章节末尾 |
| 整本书 | 本书全部正文 |

首次提问或确认生成摘要后固定对话模式；改变模式需要新建对话。
固定的是读取模式，位置可随之后的提问前进或后退。

`ScopedReading` 是原文、摘要输入与引用校验的共同边界。
历史消息和摘要还必须具有相同源指纹，且生成时边界不超过本次边界。
阅读回退后，未来范围的摘要和消息仍保留在本地历史中，但不会进入新请求；摘要展示也会隐藏。
旧格式历史缺少可信边界或指纹时只供展示。

## 问答链路

```text
用户发送 → 立即显示思考气泡 → 刷新并冻结本轮位置
        → ScopedReading 裁剪 → 校验确认引用、摘要、历史
        → ContextBuilder 按预算装配 → 一次模型调用 → 流式 Markdown
```

不再调用模型来规划检索或进行多轮工具读取。范围内正文能放进预算时按原书顺序完整发送；
超预算时，概括问题分布选段，具体问题按中文 2-gram/英文整词检索，明确标记省略。
上下文预算包含提示词、问题、原文、摘要和最近历史，发送前再次检查总量。
历史最多八条。输出上限 8192 tokens；遇到 length 提示未完成，没有正文则显示错误。

`/now` 是本地命令：刷新位置并插入位置卡片，不锁定模式、不调用模型，也不要求 API Key。
`/now 问题` 先显示位置卡片，再用该位置回答。普通问题也会刷新位置。
新对话显示起始位置卡片，输入区上方持续显示该对话最后一次验证的位置。

## 划选确认

用户在 Books 划选后点击「读取划选并确认」。有效的 AX 字符范围用于精确切分；
系统只返回整段时，预览明确说明是段落候选。用户确认预览后才附加到问题。

确认令牌绑定书籍、对话、源指纹与候选文字。发送时重新检查确认状态和授权原文包含关系。
切书、切对话、源文件改变、未确认或引用超出范围都不能借此扩大读取权限。

## 辅助章节结构

`ChapterStructure.candidates` 从本地目录、标题、独立章节标记和文档起点构造固定锚点，附带候选间长度与边界附近最多 160 个非空白 Unicode scalar 的样本。`ChapterClassifier` 是无工具、无对话历史的专用分类请求，返回固定 schema 的分类、是否独立区段、置信度。模型不返回坐标或新标题，样本不写入持久化方案。卷章层级在本地根据分类顺序连接；低置信度及未知节点保守保留为边界。

用户主动确认全书结构分析后，`StructureJobs` 冻结本地书籍 UUID、原文与结构版本、模型及预算；每批最多 6 个新候选加上前批末候选（必须一致）。每次请求校验字符和保守 token 预算，输出预留 1536 token。收到错误格式、未知/乱序/重复锚点或截断结果即拒绝。进度和完整建议保存到书籍 study；取消、源变化、删除重导入均阻止晚到结果写回。重启标记中断，不自动重试。

预览对比原/新区段数、锚点位置、类型与不确定项；确认应用前重新只读解析原书并校验来源与方案版本。`BookStudy.localStatistics` 保留本地基线，`appliedStructure` 是已确认覆盖层，`proposedStructure` 是待确认方案。刷新本地地图不会覆盖已接受结构，源/本地基线变化则失效。恢复本地结构无需调用模型。

原文坐标不变，阅读与摘要共同使用有效统计边界。`structureVersion` 包含有序边界、类型和原文校验值；摘要任务同时校验此版本，结构变化后不能写回旧任务。只复用 ID、正文指纹及起止坐标一致的章节摘要，全书摘要失效。整章对话各自保存 `confirmedStructureVersion`；版本未确认前阻止问答/摘要请求，也不展示新范围的完整摘要。读到这里仍以原文页末坐标为准，预览中的未来标题隐藏。

所有结构写入 BooksBridge 的 store.json，与书籍 UUID 关联。独立分析/应用时只读加载原书，不另写地图缓存，避免删除书籍后异步加载重新留下缓存。Apple Books 数据库、EPUB、阅读进度均不写入。

## 手动摘要

`BookStatistics` 在本地按目录与标题生成不重叠的章节边界，统计全书、章节、其他区段的字符数与保守 token 估计，并保留正文文档数。章节地图和统计不保存原文副本。

`StoredBook.libraryID` 是本 app 的 UUID，源关联沿用 assetID、sourceAliases 和指纹。`StoredBook.study` 保存统计、章节摘要、全书摘要及任务状态；同书所有对话共享。Apple Books 数据库和 EPUB 始终只读。

用户点击“生成全书摘要”后，`SummaryJobs` 每本书最多运行一个任务，冻结全书源版本；无需额外的接口信息确认框。`ChapterSummarizer` 对每章独立生成，不接收后续章节原文；超长章节分段压缩后归并，全书汇总只接收章节摘要。每次调用同时检查字符预算与用户配置的模型 token 窗口，预留提示词、输出和消息封装。UTF-8 字节数用于保守估算 token。截断或空响应不能标记为完成。

生成入口统一处理全书：使用独立 ReadingAssistant 读取本地章节，不依赖对话或页末定位，按章处理后汇总。主内容区的全文摘要文档可独立查看，默认提示含后续情节，不自动进入聊天请求。受限聊天仍只能使用边界内章节摘要和原文；全书聊天从原文构建输入。生成前的本地读取也纳入书籍任务，切换对话不取消，停止或删除会阻止晚到结果继续调用模型。

每章完成立即保存。切换、归档或删除对话不取消书籍任务。取消/重启保留已完成章节，用户继续时复用；未完成章节的内部片段不保存。原文变化后仅保留指纹和位置仍匹配的章节摘要，废弃全书汇总。删除书籍取消任务并清理 app 数据；任务同时校验 UUID、源指纹和任务代次，防止晚到结果重建删除记录。

旧对话中的全书摘要在原文指纹一致时迁入共享资料；生成新章节摘要不会自动发起付费请求。旧受限摘要保留在原记录中，不冒充章节摘要。清除共享摘要也清除旧对话摘要，避免再次迁入。

## 存储与权限

应用数据位于 `~/Library/Application Support/BooksBridge/`：

- `store.json`：书籍 UUID 与源关联、统计、共享章节/全书摘要、对话、模式、消息和位置。
- `maps/`：章节地图元数据，不含正文副本。
- `settings.json`：模型、预算、思考摘要默认展开等设置。
- `model-secrets.json`：按服务商 UUID 保存 API Key，文件权限 0600；`models.json` 保存服务商、模型与两个默认选择。旧 `secret.json` 不再参与调用路由。

已获授权时自动恢复检测；缺少权限时提供连接入口，启动不主动弹授权框。
必须通过实际读取验证完全磁盘访问权限，不能仅使用 `isReadableFile`。
签名身份和指定要求保持稳定；构建脚本验证签名成功后才替换应用。
从 Finder 或 `run-app.sh` 启动验证应用自身权限，终端直跑可执行文件不能证明其独立授权。
详见 [权限与签名](permissions.md)。

## 并发与界面

AppDelegate、ReadingAssistant、SummaryJobs 和 WebBridge 在主线程编排。
本地 EPUB 加载与状态采集通过后台任务执行；网络使用 URLSession。
切换对话会取消该视图的问答/位置任务，后台摘要持有冻结的输入继续运行。
异步结果写回时校验对话或任务代次，避免迟到结果落入其他对话。

前端通过 `window.booksbridge.onState` 接收状态，通过 WebBridge 发送指令。
API 活跃检测只发送固定短探测内容，不发送书籍。思考摘要默认折叠，可在设置中改变。

## 聊天操作与书库整理

阅读操作集中在＋菜单。前端 `actions` 注册表同时驱动菜单与斜杠命令，只有 `/now 问题` 携带问题进入模型请求；纯 `/now` 使用宿主已有的本地刷新流程，其他纯命令直接打开面板或调用对应宿主操作。未知命令保留在输入框并提示，不作为问题发送。

阅读位置在聊天时间线中居中显示，顶部不再提供可点击的进度或摘要状态。划选是临时确认卡片，确认后可折叠；全书摘要占据主内容区，支持返回对话，章节工具默认收起。进度、停止和继续生成集中在文档内，重新生成及清除收进操作菜单。

书籍顺序直接使用 `StoredState.books` 的数组顺序；`moveBook` 移动完整记录，保留所有对话。侧栏拖拽和上移/下移菜单共用该操作。没有变化的侧栏状态不重建 DOM，拖拽期间也不重建。

归档使用可选 `Conversation.archivedAt` 字段，旧数据默认未归档。归档不删除消息、位置、权限或摘要；归档当前对话时切到同书未归档对话，若没有则等待用户新建。归档视图可查看历史，恢复后才能继续提问。摘要任务独立于归档状态继续运行。打开一本书时只选择未归档对话；若全部归档则新建一条。

阅读位置用 `isPositionCard` 元数据保存并排除于模型历史；前端呈现为居中灰色分隔行，兼容旧卡片并隐藏旧 `/now` 用户消息。独立 `refreshPosition` 只做本地刷新，连续刷新替换末尾标记；提问刷新后将新位置插入用户问题之前。


## 多服务商与模型路由

`ModelCatalogStore` 维护服务商和模型 UUID。聊天保存 conversation.modelID，摘要保存 book.summaryModelID；默认值只用于尚未选择的用途。删除或停用不自动替换引用。每次调用解析为不可变 ModelConnection，冻结 URL、Key、模型参数；消息保存 ModelStamp，避免历史标签随配置变动。摘要另存生成时的配置版本，续作必须匹配，否则保留结果并要求重新生成。

界面 `models.js` 管理服务商表单、模型编辑、显式列表获取、显式活跃检测以及聊天/摘要选择器。密钥仅支持替换和清除，不回传。打开设置、切换模型和对话不会触发模型请求。仅支持 OpenAI 兼容 Chat Completions；基础路径原样保留，温度和 thinking 扩展按模型配置选择发送。聊天同时校验字符预算与模型输入空间，超限时缩减允许范围内的检索材料和历史，不截断问题或权限提示。

模型列表使用按服务商 UUID 分开的会话内状态（列表、搜索、勾选、滚动位置），独立于设置 DOM。目录比较采用键排序的语义签名，后台阅读推送不重建相同配置。连接 revision 改变后旧响应不能覆盖列表，必须显式刷新后才能批量导入；刷新失败保留选择，已不在新列表中的选择标为不可用。`addModels` 校验服务商和 revision，以服务商内 remoteID 去重，在一次存储事务中添加全部新模型，保留已有参数、UUID 与默认选择。界面关闭和导航不发请求，只有获取/刷新按钮请求列表。
