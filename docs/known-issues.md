# 已知限制与未验证项

这份文档刻意把「确定做不到」「已知取舍」「尚未验证」分开写，
避免把未测过的东西当成能用。

---

## 一、确定做不到

### 不能上架 Mac App Store

读取图书 App 的沙盒容器需要完全磁盘访问权限。沙盒化的 App Store 应用无法获得，
审核也几乎必然拒绝。只能走开发者 ID 签名直接分发。

### 不能分发给别人

本项目用本机自签名证书。该证书在别人机器上不受信任，且无法公证。
**仅限自用。**

### 没有第三方插件机制

见 [findings.md](findings.md)。
不存在「写个插件挂进图书 App」这条路，只能从外部旁路读取。

### 页面定位依赖可见文字

CFI 偏移不能直接用于切片。现在通过当前阅读窗口可见文字与 EPUB 原文匹配定位页尾。
Books 分栏容器可能上报屏幕外坐标，采集时仍遍历其子节点并验证文字坐标；跨页段落按可见字符范围或字符几何裁切。
只使用已验证可见的文字定位边界；无法验证的页尾可能少读。重复段落、图片页或无法识别的排版仍可能无法定位，此时停止受限请求，不扩大权限。
对话中的「检查原文范围」只在本地运行，显示章节、位置与可读字数，不调用 API。
同名书籍无法唯一匹配时也停止检测。不同 Books 版本、双页和多显示器仍需持续实机验证。

## 二、已知取舍

### 大书超出预算时仍使用选段

范围内的原文放得下时直接完整发送。超出预算时，概括问题按书中位置分配选段，具体问题使用中文 2-gram + 英文整词打分。选段不等于完整阅读，缺口会标明。

**代价**：语义相近但用词不同的内容检索不到（例如问「主角为什么害怕」，
而原文写的是「他浑身发抖」）。现在使用确定性的本地装配与一次模型请求，不保证检索穷尽所有相关段落。

### 摘要后台任务

摘要按书籍和对话独立运行，输入冻结为用户确认的读取范围。切换对话、书籍或设置不取消。侧栏显示状态，切回会恢复该对话进度；取消必须显式操作。
任务状态与书名保存在本地；应用退出会停止网络任务，重启后显示中断，需手动重新生成，不会自动重发收费请求。
目前不保存分块中间结果，因此中断后重新生成会重新处理所选范围。

### 旧缓存指纹迁移

章节地图、位置和范围摘要统一使用完整正文 SHA-256 指纹。旧版整书摘要不自动导入新对话；旧消息若缺少指纹/边界，只展示而不送入模型。不会自动发起付费重建。

### API Key 明文落盘

存在 `secret.json`，权限 **0600**（仅当前用户可读），没有用 Keychain。

**原因**：Keychain 对未签名的本地应用每次读写都可能弹授权框，对自用工具摩擦过大。

**代价**：同机其他进程若以你的身份运行即可读取。

### 对话历史有预算与范围限制

最多 8 条，并受总请求字符预算及当前阅读边界限制。未标记边界或源指纹的旧历史不会送入模型。
更长对话会丢掉较早的轮次。

### PDF 只有书名和进度

PDF 的位置是页码而非 CFI，走的是另一条路线，当前未实现。
界面上能看到这本书，但取不到正文。

### 预处理是花钱的操作

点击「生成阅读摘要」并确认后会触发预处理（短书 1 次调用，长书 map-reduce 多次）。
一本 10 万字的书大致消耗十几万 prompt token。

**缓解**：结果按对话保存并记录源指纹和读取边界，只有用户确认才生成；失败时仍可
直接使用本地原文（预算容得下时完整提供，超出时选段），不阻塞使用。

## 三、尚未验证

以下功能仍有未完成的真实环境验收项。
使用前请留意。

### LLM 基础问答已试用，复杂场景待验证

2026-10-14，用户配置 API Key 后完成了基础问答试用，并确认可用。
这不等同于长书预处理、所有服务商及成本表现均已完成端到端验收。

已验证的部分（有测试覆盖）：
- SSE 流式解析（含 `[DONE]`、带 usage 的末条 chunk、空 delta、畸形行）
- 请求体构造（模型、`thinking` 对象、`stream_options.include_usage`）
- URL 规范化（带/不带 `/v1`、带尾斜杠、自定义端点）
- 提示词组装与范围约束
- 上下文检索与字符预算

**未验证**：
- 真实 API 返回的结构是否与解析器完全吻合
- 预处理产出的「书籍说明」质量如何
- 长书 map-reduce 的实际效果
- 流式渲染在前端的表现
- 实际 token 消耗与费用

**首次使用建议**：先拿一本短书试，开「关闭思考模式」，
问一个简单问题确认链路通，再做长书预处理。

### ⚠️ 划选的字符级精度未验证

`AXSelectedText` 返回的可能是**整个段落**而非用户划的那几个字（实测三次里两次如此）。
有有效 `AXSelectedTextRange` 时精确切分；否则明确展示整段候选，要求用户确认。
发送前检查引用仍在当前范围内。自动测试覆盖范围校验，更多书籍排版下的字符级精度仍需实测。

### 未验证的界面行为

- 状态栏书本桥图标 的实际点击（系统返回 -25204，无法自动化）
- 原生全屏下状态栏图标是否可见（全屏空间可能盖住菜单栏）
- 多显示器下的窗口摆放（只在单屏验证过）

## 四、环境相关

### 只在单机验证过

所有实测数据来自 macOS 27.0.1 / 图书 9.0 / Apple Silicon。
苹果图书的内部结构随版本变化，换版本可能失效。

### 依赖图书 App 的数据格式

`BKLibrary` / `AEAnnotation` 的表结构、`kLastCurrentBookKey` 键名
都是实测逆向得到的，非公开接口。苹果改版即可能失效。

代码对此的防护：所有查询都做了字段缺失兜底（缺字段退化为默认值而不是崩溃），
数据库找不到时降级而非报错。

### 书未下载完时取不到正文

EPUB 被解包成目录，但若书未完整下载，manifest 声明的 xhtml 可能不在磁盘上。
实测 235 本里只有 1 本如此。导入明确报错，不以缺失正文构造不完整地图。

## 五、安全与隐私

- 提问时会把**权限范围内的完整原文或选段，以及适用的范围摘要**发送到配置的接口
- 书籍内容因此离开本机
- 若在意隐私，可把接口地址指向本机 Ollama（设置里已支持，不需要 API Key）
- API Key 明文存于 `secret.json`（0600）
- 应用不采集任何遥测
