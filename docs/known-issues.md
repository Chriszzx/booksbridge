# 已知限制与未验证项

这份文档刻意把「确定做不到」「已知取舍」「尚未验证」分开写，
避免把未测过的东西当成能用。

---

## 一、确定做不到

### 不能上架 Mac App Store

读取图书 App 的沙盒容器需要完全磁盘访问权限。沙盒化的 App Store 应用无法获得，
审核也几乎必然拒绝。只能走开发者 ID 签名直接分发。

### 不能分发给别人

本项目用本机自签名证书。该证书在别人机器上不受信任，且无法公证。
**仅限自用。**

### 没有第三方插件机制

见 [findings.md](findings.md)。
不存在「写个插件挂进图书 App」这条路，只能从外部旁路读取。

### 无法在章内定位

CFI 偏移不是章节内位置（见 [findings.md](findings.md)）。
所以做不到「只给读者读到的那半章」—— 范围边界只能落在章节上。

## 二、已知取舍

### 关键词检索而非向量检索

`ContextBuilder.search` 用中文 2-gram + 英文整词打分，零依赖、零额外成本、结果可解释。
单本书（十几万字）规模下够用。

**代价**：语义相近但用词不同的内容检索不到（例如问「主角为什么害怕」，
而原文写的是「他浑身发抖」）。跨书检索时这个局限会更明显。

### 内容指纹允许漏判

`BookPreprocessor.contentHash` 用长度 + 首尾 + 均匀 64 点采样。
**单个内部字符的改动可能不被发现**（40 万字里改一个字，若不在采样点上）。

这是刻意取舍：指纹的用途是判断「这本书还是不是原来那本」，
换书与截断（首尾会变）都能覆盖。真要逐字校验应改用完整哈希。

### API Key 明文落盘

存在 `secret.json`，权限 **0600**（仅当前用户可读），没有用 Keychain。

**原因**：Keychain 对未签名的本地应用每次读写都可能弹授权框，对自用工具摩擦过大。

**代价**：同机其他进程若以你的身份运行即可读取。

### 对话历史最多带 8 条

`PromptBuilder.build(maxHistoryMessages: 8)`。避免上下文无界增长。
更长对话会丢掉较早的轮次。

### PDF 只有书名和进度

PDF 的位置是页码而非 CFI，走的是另一条路线，当前未实现。
界面上能看到这本书，但取不到正文。

### 预处理是花钱的操作

打开一本书会触发一次整本书预处理（短书 1 次调用，长书 map-reduce 多次）。
一本 10 万字的书大致消耗十几万 prompt token。

**缓解**：结果按内容指纹缓存，同一本书只做一次；失败时提问会退化为
「只用原文片段」，不阻塞使用。

## 三、尚未验证

以下功能**代码已写、单元测试已过，但没有在真实环境端到端跑通过**。
使用前请留意。

### ⚠️ LLM 问答的完整链路未实测

**原因**：开发过程中没有可用的 DeepSeek API Key，无法发起真实请求。

已验证的部分（有测试覆盖）：
- SSE 流式解析（含 `[DONE]`、带 usage 的末条 chunk、空 delta、畸形行）
- 请求体构造（模型、`thinking` 对象、`stream_options.include_usage`）
- URL 规范化（带/不带 `/v1`、带尾斜杠、自定义端点）
- 提示词组装与范围约束
- 上下文检索与字符预算

**未验证**：
- 真实 API 返回的结构是否与解析器完全吻合
- 预处理产出的「书籍说明」质量如何
- 长书 map-reduce 的实际效果
- 流式渲染在前端的表现
- 实际 token 消耗与费用

**首次使用建议**：先拿一本短书试，开「关闭思考模式」，
问一个简单问题确认链路通，再做长书预处理。

### ⚠️ 划选的字符级精度未验证

`AXSelectedText` 返回的可能是**整个段落**而非用户划的那几个字（实测三次里两次如此）。
`AXSelectedTextRange` 是否可用**尚未验证**。

影响：当前设计是「就某一段提问」，没有做「划词就地问」。
`AccessibilityReader.preciseSelection` 已实现精确切分逻辑，但未在真实划选上确认。

### 未验证的界面行为

- 状态栏 `BR` 的实际点击（系统返回 -25204，无法自动化）
- 原生全屏下状态栏图标是否可见（全屏空间可能盖住菜单栏）
- 多显示器下的窗口摆放（只在单屏验证过）

## 四、环境相关

### 只在单机验证过

所有实测数据来自 macOS 27.0.1 / 图书 9.0 / Apple Silicon。
苹果图书的内部结构随版本变化，换版本可能失效。

### 依赖图书 App 的数据格式

`BKLibrary` / `AEAnnotation` 的表结构、`kLastCurrentBookKey` 键名
都是实测逆向得到的，非公开接口。苹果改版即可能失效。

代码对此的防护：所有查询都做了字段缺失兜底（缺字段退化为默认值而不是崩溃），
数据库找不到时降级而非报错。

### 书未下载完时取不到正文

EPUB 被解包成目录，但若书未完整下载，manifest 声明的 xhtml 可能不在磁盘上。
实测 235 本里只有 1 本如此。此时只能定位到章名，取不到正文。

## 五、安全与隐私

- 提问时会把**书籍说明与相关原文片段**发送到配置的接口
- 书籍内容因此离开本机
- 若在意隐私，可把接口地址指向本机 Ollama（设置里已支持，不需要 API Key）
- API Key 明文存于 `secret.json`（0600）
- 应用不采集任何遥测
